数据编织：为什么 · 是什么 · 由什么组成

约束为何出现 → 可操作定义是什么 → 能力如何分层组成。三者闭环，避免把 Fabric 当成新名词或采购清单。

叙事主轴
1为什么会出现 → 2它是什么 → 3由什么组成
01

为什么

不是行业需要新名词，而是点对点集成与强制集中同时碰到规模边界。

点对点 → 组合爆炸

每个源为每个消费者建专用管道，变更沿依赖链扩散；隐性映射越多，维护越脆弱。

全部集中 ≠ 免费

驻留、出云、边缘时延、源负载与主权仍在；把数据放一起也不会自动统一语义。

潜在连接上界 ≈ n(n−1)/2　·　10→45　·　100→4,950　·　1,000→499,500
六种同时增长的异构性
位置多云 / 边 / 伙伴 结构表 / 流 / 向量 速度批 / CDC / 实时 语义同名异义 治理用途 / 驻留 消费人 / API / AI
第一性约束：数据有重力，计算有位置，语义属领域，责任属组织——按场景选择「数据移动 / 查询移动 / 模型移动」。
因此：需要逻辑控制面连接分布式数据，而不是更多点对点管道，也不是无条件物理大集中。
02

是什么

对「为什么」的架构回答：设计方法与能力组合，而非某一件软件。

跨异构、分布式环境的数据管理与集成设计：以技术/业务/运营/使用元数据知识网络为控制面，观察数据与使用行为并推荐或执行发现、集成、质量、安全、编排与交付；在不强制统一物理存储的前提下，交付可组合数据产品。
技术元数据schema · 血缘 · 作业
业务元数据术语 · 指标 · 实体
运营元数据SLA · 成本 · 健康
使用元数据查询 · 消费 · 反馈

经线 · 治理

身份、术语、策略、契约、血缘与责任骨架。

纬线 · 流转

批 / CDC / 流 / 联邦 / API，按 SLA 选择交付。

织机 · 主动

观察 → 推断 → 推荐/执行 → 反馈闭环。

≠ 中央湖仓≠ 被动目录≠ 单靠虚拟化 ≠ 仅 ETL≠ 厂商产品名
03

由什么组成

把定义拆成可建设能力：六层 + 横切保障（分析框架，非正式标准）。

L6
消费与行动BI / API / RAG / Agent / 闭环
L5
数据产品与自助Marketplace · 契约 · 语义 · SLO
L4
主动元数据控制面Catalog · Lineage · Policy
L3
集成编排查询ETL · CDC · Stream · Virtualization
L2
数据与 AI 运行时Lakehouse · Feature/Vector · PET
L1
分布式权威源DB · Lake · Event · Edge · Space
横切
身份 · 质量 · 安全 · 隐私 · 审计 · 可观察

L4 控制面回答「应该怎样」；L1–L3 数据面决定「在哪里、如何执行」。逻辑统一 ≠ 物理集中。

逻辑链：异构约束 → 主动元数据控制面 → 分层能力；对齐深度调研与 Gartner/IBM 公开表述

数据编织成熟度：能力闸门 G0—G5

成熟度不是采购清单打分，而是可验证的能力闸门：先可观察、再产品化、再影子闭环，最后才有界自治与跨域供给。

证据驱动 · 非口号驱动
G0BOUND

边界、对象与词汇

明确场景目标；为关键对象、数据、模型与动作指定 Owner、时间语义、版本、保留期与权威源。

G1SEE

只读可观察

接入关键源，建立目录、Schema、事件时间、QoD 与血缘；先证明能回答「哪份数据对应哪个状态」。

G2PRODUCT

数据产品与契约

高频复用输出封装为产品；CI 校验兼容性、质量、用途与成本；无人使用的资产应退出。

G3SHADOW

影子闭环

系统只给建议，对照人工决策与真实结果；高风险动作先在沙箱/孪生中演练。

G4BOUND-AUTO

有界自治

仅对白名单、低风险、可回滚动作自动执行；配置风险预算、熔断与人工接管。

G5SUPPLY

跨域可信供给

内部语义与质量稳定后，再向外部域/伙伴/上层系统供给最小必要的数据产品。

进入 G0 之前：最小充分性

  • 异构来源长期共存，且跨域复用频繁
  • 语义冲突显著，变更影响难追踪
  • 治理约束复杂（用途、驻留、责任边界）
  • 已有明确场景、Owner 与可量化结果

对应胶片1的六种异构与第一性约束。同时满足至少三项，才进入 G0；否则先解最窄瓶颈，不预付控制面复杂度。

建议跟踪的成熟信号

新鲜度 / 完整率消费时间相对源事件时间；必需字段实收比 → G1+
血缘覆盖 / 发现时延关键产品可追至源与动作；变更感知时延 → G1+
产品复用率≥2 独立消费者稳定使用；重复采集下降 → G2+
闭环有效性Deadline 达标、无效动作率、回滚耗时 → G3+
边界提醒：Gartner 将 Data Fabric 视为新兴设计组合，组件成熟度不一，尚无单一 ISO/ITU/3GPP「Data Fabric 产品」标准。G4/G5 的自治与跨域供给必须以 G1–G3 证据为前提；成熟标志不是「无人」，而是边界明确、证据完整、可回滚。
闸门模型综合调研中的能力演进逻辑；组织应按场景裁剪，不可跳级宣称「自治」

演进趋势：从集成层到可信智能控制面

2026—2035 不是十项独立产品清单，而是一条因果链：分布驱动元数据事件化 → 机器消费驱动语义显式化 → 自动化驱动策略与可回滚性。

事实 / 推演分层
高确定性

元数据事件化

Catalog 从定时扫描升级为事件驱动；schema/质量/权限变化触发影响分析与策略复核。

高确定性

语义控制平面

版本化 ontology / 知识图关联实体、指标、产品、模型、Agent 工具与政策。

高确定性

产品与契约即代码

Schema、SLA、许可、用途进入机器可读契约与 CI；开放规范兴起但未全球统一。

高确定性

流批与开放 Catalog

CDC/流/增量表/快照视为同一事实的不同延迟视图；竞争上移到 Catalog 与策略。

快速演进

Agent 可操作 Fabric

先辅助检索、草拟、调查与编排；再在最小权限与审计下执行低风险动作。

快速演进

RAG 成为治理路径

向量召回叠加图/SQL/血缘/权限；答案追溯到数据产品，防投毒与提示注入。

中高确定性

PET + 机密计算

差分隐私、MPC、联邦学习与 TEE 按场景组合；证明环境≠证明用途合法。

中等确定性

接入外部 Data Space

凭证、合同协商、用途策略与连接器；跨组织交换仍需法律与审计共约束。

因果链
数据分布 → 元数据事件 → 显式语义 → 有界自动化 → 策略·证明·回滚

与胶片2对齐：工程底座≈G1–G2；语义策略≈G3–G4；条件性自治≈G4–G5（仍受证据与风险预算约束）。

2026—2027

工程底座

事件化元数据、血缘、数据契约、开放 Catalog、受治理 RAG 与 Agent 辅助成为平台基线。

2028—2030

语义与策略控制

ontology 连接数据、模型、政策与动作；低风险建议可自动执行，高风险操作由仿真、审批与回滚护栏约束。

2031—2035

条件性自治

自动映射、异常调查、管道优化、边云放置更成熟；跨企业自主签约与完全无人治理仍属低确定性判断。

研究快照口径 · 区分高确定性工程趋势与中长期推演；不构成产品承诺
