# 执行摘要 · 6G 数据面的数据编织技术洞察

> 配套主报告：`reports/deep-insight-report-v6.md`。出品：公司战略专家组。生成 2026-07-21，修订 2026-07-25（趋势三/四/五更换为数据编织硬技术趋势）。

## 一句话定位

6G 数据面把网络变成公司主航道上最大的新数据场景，但数据面只解决数据的**运输**，不解决**成品化**——**数据编织（且是被 AI 重写过实现方式的版本：LLM 建语义、Agent 管数据、合约固治理、意图做接口）是把管道变成可售卖数据与智能服务的必要底座**；今天的编织离数据面的真实需求还差六项技术，这份差距清单即我司未来三年在该方向的立项清单。

## 核心判断（按信心降序）

1. **数据编织是 6G 数据面的路线无关（route-agnostic）必选项** [高]
   "需要数据编织"与"需要独立数据面"是两个独立命题：GTP-U/UPF 之弊论证传输层重构，NWDAF 无目录/无语义/无跨域之缺才论证数据编织。无论 SA2 2027 年裁决独立面还是增强用户面，统一数据管理与语义层都是共识——全部建议不押注标准结果。
2. **2026–2027 是数据管理条目定义权的收敛窗口** [高]
   ETSI ZSM 029（我司参与主导，2026-04 采纳）与 3GPP SA2 WT#5（2027-03 方向性结论）同期收敛；**编织层与数据面之间的接口至今零标准化提案**，"数据管理层的量化时效需求"在公开文献中也是空白——两个都是可抢先定义的条目。
3. **两处流行口径必须校准，否则误导投资** [高]
   ①"亚毫秒"（O-RAN dApp <1ms）是实时控制闭环的需求，**不是数据管理层需求**——编织的真实主战场在秒级近实时层（流式元数据标注不拖慢遥测管道）与分钟级管理面；②"ZB 级/天"是空口原始产生量的厂商单方估算（1 ZB ≈ 5,000 万块 20TB 硬盘/天，不可存储不可回传），它论证的是"数据须在产生点被筛选、降维、理解"，**不是存储/传输投资的依据**。
4. **AI 对数据编织的加持已从概念进入产品与实证阶段** [中高]
   需求侧：63% 组织缺 AI-ready 数据实践、60% AI 项目将因此被弃（Gartner 1,203 人调查）。供给侧四条路径有硬证据：LLM 自动构建电信知识图谱（GSMA 开源 O-RAN/3GPP 规范 KG）；Agentic 数据管理产品化（Informatica/IBM 2026 年 GA，接口收敛 MCP）；AI 生成机器可验证数据合约（Gartner 2026 预测）；意图驱动供数（Agentic-NWDAF 电信原型验证）。
5. **编织的底座与执行内核正在换代——两条硬技术趋势直指 6G 工程约束** [中高]
   底座侧：遥测数据的落场收敛到"开放表格式（Iceberg 事实标准）+ 流式湖仓（Paimon/Fluss 秒级）+ 开放目录"，Kafka 流可直接物化为表——编织重心从"连接一切"上移到目录/语义/治理，电信化省掉一半连接器工程（DT ODE 三层 Iceberg 已投产）。内核侧：可组合引擎（Arrow 零拷贝 + 可嵌入查询引擎 + 计划下推）+ eBPF 内核级采集，使"把查询/标注/策略推到数据产生点"首次工程可行——边缘原生编织的 PoC 成本较三年前降一个量级，且 IT 编织巨头无 RAN 触点走不了这条路。
6. **编织的数据类型体系扩展：多模态感知与向量嵌入成为一等公民** [中]
   6G ISAC 产出 I/Q/CSI/点云等企业编织没见过的数据类型，嵌入正在成为跨模态通用中间表示（数据库侧向量已一等公民化）；网络侧已启动感知数据存储（SDSF 提案）与感知服务模型（E2SM-SENS），但**感知数据的元数据模型、语义与索引无人定义**——叠加 LLM 把语义层建造成本数量级拉低（GSMA 开源电信 KG），先建者定义事实标准。（试点侧：DT/LG U+/Vodafone 先行均为供应商口径，2027–2028 预计扩至 5–6 家 Tier-1，国内首发位空缺；Mesh-on-Fabric 终局未证 [低]。）

## 需求与结合点（对应链：D# → 结合点 → 鸿沟 → 议程 → 趋势 → 机会）

数据面对数据管理层的五项需求：**D1** 统一数据框架（SA2 WT#5"一次采集多次使用"）、**D2** AI 原生供数（NWDAF 三局限倒逼）、**D3** 感知数据服务化（变现的合规前提）、**D4** 数字孪生供数、**D5** 跨域合规流动。编织七项能力对 D1–D5 逐项有承接方案/原型；价值定位：**编织不解决"跑得快"，解决"被找到、被理解、被信任、被合规地使用"**。鸿沟集中在秒级近实时层与协议对接（管理面已有落地、实时控制闭环不属编织战场）。

## 六项技术演进议程（预研与标准投入的立项清单）

流式/近实时编织（O1）→ 电信协议原生连接器与编织-数据面接口（O3）→ 多模态电信语义层·LLM 自动构建（O2/O3）→ 边缘原生形态（O1/O6）→ 线速治理与数据合约（策略 7）→ Agentic 供数接口·MCP/意图（O2）。AI 加持贯穿六项而非独立一项；六项与六条趋势、六个机会逐项挂钩（标准窗口与试点节奏在主报告现状五与机会 O6 承载）。

## 对我司的 3 条建议

1. **短期（≤6 个月）**：起草"数据引擎→6G 数据框架组件"战略白皮书（含主航道绑定论证：设备竞标差异化正从连接性能移向数据与智能能力，数据编织是主航道产品的横向公共组件）；SA2 WT#5 提交语义模型/数据服务接口提案 ≥1 篇；ZSM 029 贡献参考实现。
2. **中期（12–18 月）**：两项预研同组推进——网络语义层自动构建（Fault Agent KG + LLM 抽取管道，GSMA 开源 KG 冷启动）、数据引擎 MCP 工具化与意图供数接口；RAN 域流式编织轻量 PoC（秒级在线标注，不进入 <1ms 控制路径，时间盒）。
3. **长期（24+ 月）**：合规参考架构（联邦 + 策略即代码 + AI 数据合约）；建议承载 SLA 映射、终端轻量编织纳入公司 6G 路标（不自担投入）。

## 主要风险

- **能力固化**：数据引擎若被固化在故障运维单场景，将错过 6G 数据框架窗口 → 以标准身位与主航道绑定对冲，建议跨线虚拟团队。
- **补位而非领跑**：华为 DaaS 术语先入为主 → 聚焦其薄弱又属我司数据引擎主场的条目（语义/接口/编排/治理）。
- **需求与叙事超前**：RAN/终端编织付费需求未明；Agentic 数据管理产品无独立客户 ROI；LLM 电信实体抽取精度无公开基准 → 需求驱动 + 时间盒 + 先自用验证。
